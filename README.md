# 도쿄·요코하마 여행 공동 저장

## 기존 GitHub Pages 주소에서 함께 편집

GitHub Pages는 저장소 루트의 `index.html`, `stage2.js`, `stage2.css`를 제공한다. 공동 저장 서버는 Node.js 24 이상을 지원하는 HTTPS 호스트에서 `node server.mjs`로 실행한다. 두 배포에 같은 버전의 코드를 사용한다.

| 서버 환경 변수 | 값 |
| --- | --- |
| `TRIP_ORIGIN` | 공동 저장 서버의 HTTPS 주소. 경로와 마지막 슬래시 없이 입력한다. |
| `TRIP_PAGES_URL` | 현재 여행 페이지 주소 `https://jimmy6706.github.io/to-tokyo/` |
| `TRIP_ROOM_KEY` | 공동 편집 키. 아래 명령으로 한 번 생성하고 서버의 비밀 환경 변수로 보관한다. |
| `TRIP_HOST` | 호스팅 환경에서는 `0.0.0.0` |
| `PORT` | 호스팅 환경에서 지정하는 포트. 기본값은 `8787`이다. |
| `TRIP_DB` | 재배포 뒤에도 남는 쓰기 가능한 영구 볼륨의 SQLite 경로. 예를 들어 `/data/trip.sqlite`을 사용한다. |

```sh
node -p "require('node:crypto').randomBytes(32).toString('base64url')"
```

`TRIP_ORIGIN`, `TRIP_PAGES_URL`, `TRIP_ROOM_KEY`가 설정된 환경에서 `node server.mjs room-link`를 실행해 주소를 만든다. 기존 여행 페이지 주소 뒤에 공동 편집용 프래그먼트가 붙는다. 이 링크를 필규·인혜·유선에게 전달한다. 받은 사람은 자기 이름만 고르면 되고, 브라우저가 다음 방문에도 선택을 기억한다. 상단 **공유 → 일행 링크**에서 같은 링크를 다시 복사할 수 있다. 새 기기에서도 이 주소로 들어온다.

일행 링크를 가진 사람은 세 이름 중 하나를 고를 수 있다. 공동 편집 키는 GitHub에 커밋하지 않는다. 키를 교체하면 새 일행 링크를 발급한다. 일반 여행 주소를 새 브라우저에서 열면 일정과 브라우저에 저장된 체크를 볼 수 있다.

## Node 서버에서 일회용 초대로 직접 열기

```sh
node server.mjs
```

같은 폴더에서 별도의 터미널을 열고 대표 멤버의 일회용 링크를 만든다.

```sh
node server.mjs invite-owner
```

링크를 열면 필규로 참여한다. **공유 → 일행 초대**에서 인혜·유선의 링크를 발급할 수 있다. 멤버 초대는 3일 동안 유효하며 한 번만 쓸 수 있다. 발급한 미사용 초대는 같은 메뉴에서 회수한다. 동일한 멤버를 새 기기에 연결할 때는 그 멤버의 초대 링크를 다시 만든다. 일정 보기 링크는 읽기 전용이고 7일 후에 만료된다.

기본 서버 주소는 `http://127.0.0.1:8787/`이다. 일행 기기에서 사용하려면 이 서버를 HTTPS로 배포하고, 공용 접속 주소를 `TRIP_ORIGIN`에 설정한다. 호스팅 환경에서는 `PORT`, 필요하면 `TRIP_HOST`를 지정한다. 프록시는 공개 주소의 Host 헤더를 보존해야 한다. `TRIP_DB`는 재배포 뒤에도 남는 쓰기 가능한 영구 볼륨의 파일 경로로 지정한다. 서버와 초대 발급 명령에는 동일한 설정을 적용한다.

기본 데이터베이스는 `.trip-data/trip.sqlite`이며 서버가 실행 계정만 읽고 쓸 수 있도록 권한을 설정한다. 파일에 체크·메모와 인증 데이터가 함께 들어 있으므로 공개 정적 디렉터리에 두지 않는다. 서버는 웹 페이지와 필요한 CSS·JS만 제공한다.

같은 여행 서버의 다른 로그인 세션은 몇 초 간격으로 변경을 읽는다. 개별 체크는 항목과 멤버를 기준으로 저장한다. 공동 항목, 메모, 참고 링크의 동시 편집에서는 마지막으로 읽은 수정 번호를 검사한다. 응답이 끊긴 작업을 다시 보낼 때에는 같은 요청 ID를 사용한다. 기존 브라우저의 로컬 체크와 캐릭터 선택은 공동 저장 서버의 별도 기록과 합쳐지지 않는다.
